# Context degradation in LLMs: absolute tokens or percentage of the window?

**Date:** 2026-09-03
**Question:** What public, high-trust evidence exists for the claim that LLM output quality degrades as the amount of content in the context window grows — and specifically, does that degradation track the *absolute* number of tokens in context, or the *percentage* of the context window consumed? Stress-test in particular: "A model with a 1M-token context window does not have a proportionally larger 'good performance' zone than a 200K-token model — a bigger window buys a longer degraded zone, not a bigger high-quality zone."
**Method:** Primary sources only — arXiv papers (abstracts and, where fetchable, methodology/results text pulled directly from the paper), Anthropic's own engineering blog and product docs, and one non-peer-reviewed but frequently cited industry technical report (Chroma's "Context Rot," explicitly flagged as such). No secondary blog summaries, no social-media threads, are treated as evidence — where practitioner claims are mentioned at all, they are explicitly labeled as unverified practitioner discourse. All sources were fetched live on 2026-09-03. Where a paper's methodology could not be confirmed from the fetched text, that is stated rather than inferred.

---

## Executive summary

### 1. Well established

- **LLM performance on synthetic long-context retrieval and reasoning tasks degrades as absolute input length grows, well before the model's advertised context limit is reached.** This is the single most consistently replicated finding across independent, methodologically distinct studies: Liu et al.'s "Lost in the Middle" (positional degradation within fixed-length inputs), NVIDIA's RULER (degradation with increasing absolute length across 17 models), NoLiMa (11 of 13 models drop below 50% of their short-context baseline by 32K tokens), and Chroma's Context Rot report (18 models, degradation as absolute token count rises, including on tasks with no retrieval difficulty). This is now also true in a peer-reviewed venue: Du et al. (EMNLP 2025 Findings) show degradation of 13.9–85% as a function of absolute input length even under *perfect, verified retrieval* — i.e., length itself, not retrieval failure, is doing damage.
- **This degradation is a gradient, not a cliff at the context-window boundary.** Anthropic states this explicitly in its own Claude Code documentation: "context rot is the observation that model performance degrades as context grows because attention gets spread across more tokens, and older, irrelevant content starts to distract from the current task," and separately that the underlying transformer mechanism creates "a performance gradient rather than a hard cliff." This is consistent with every quantitative study above.
- **A larger claimed/maximum context window does not guarantee good performance at a given absolute length, and does not track with claimed window size.** RULER's most direct finding: at fixed absolute lengths (4K/8K/16K/32K/64K/128K, tested identically across models regardless of each model's claimed maximum), "while these models all claim effective context of 32K tokens or greater, only half of them can maintain satisfactory performance at the length of 32K," and one model trained for a 1M-token window ("LWM") "performs worse than Llama2-7B even at 4K." This is genuine same-absolute-length, cross-window-size evidence, and it points the same direction as the practical claim under test: bigger claimed windows do not buy proportionally bigger "good performance" zones.
- **Needle-in-a-haystack (NIAH) results are a benchmark description, not free-standing evidence for degradation dynamics.** Greg Kamradt's original NIAH methodology (November 2023) is the origin of the visualization and test format widely cited in this space, but it is a practitioner-authored benchmark writeup, not a peer-reviewed or otherwise vetted study; it is treated here purely as the definition of the benchmark that later academic work (RULER, NoLiMa, Chroma's report) builds on and critiques.

### 2. Plausible but under-evidenced

- **The absolute-tokens-vs-percentage-of-window framing, as a general law across arbitrary model pairs.** RULER's finding (above) is consistent with the claim and is the closest thing to direct evidence found, but RULER only tested models up to 128K–200K native windows in the original paper (2024) and did not set out to test this dichotomy as its stated research question — it was testing "effective" vs. "claimed" context length, which is adjacent to, not identical to, the absolute-vs-percentage question. No study in this search independently varied *both* absolute length *and* window size on a matched task in a way designed to isolate whether percentage-fill or absolute-token-count is the causal driver of degradation onset. See "Unsupported" below.
- **Degradation in real-world agentic coding task quality (multi-turn tool use, code editing over accumulated context) as a function of context length.** One EMNLP 2025 Findings paper (Du et al.) includes coding tasks in its 5-model evaluation and finds degradation from length alone — this is the strongest evidence found for claim (b) in the prompt (agentic/coding quality vs. context length), but it is still single-turn code-reasoning-style tasks evaluated with an automatic checker, not multi-turn agentic tool use, file editing, or long-running coding-agent sessions. No primary source in this search directly measures coding-agent output quality (e.g., correctness of a multi-file patch, or agentic task success rate) as an explicit function of accumulated conversation/tool-output tokens.
- **"Context rot" as a term with a settled, quantitative, cross-model absolute-token definition.** Anthropic's own docs attribute the term and its evidentiary basis to Chroma's report, and Chroma's report is a well-documented, methodologically serious industry technical report (18 models, multiple task families, code and reproduction materials released) — but it is not peer-reviewed, and by its own analysis section, it does not normalize or compare degradation curves as a percentage of each model's context window versus absolute position; it evaluates each model largely at its own native maximum lengths.

### 3. Unsupported

- **No study found in this search independently manipulates both (a) absolute input token count and (b) a model's maximum context window size, in a design built specifically to test whether degradation onset tracks absolute tokens or percentage-of-window.** This is the direct test the practical claim needs, and it does not appear to exist in the public literature as of this search. RULER's cross-model, same-absolute-length results are adjacent and directionally consistent, but RULER's own framing is about the gap between *claimed* and *effective* context length, not an explicit absolute-vs-percentage ablation.
- **The specific quantitative shape of the claim — "a bigger window buys a longer degraded zone, not a bigger high-quality zone"** — is not directly measured or stated by any primary source found here. It is a reasonable extrapolation from RULER's findings and from Anthropic's own "gradient, not a cliff" language, but no source draws this precise conclusion or reports a "good performance zone" size as a function of window size.
- **Any claim that degradation onset (in tokens) is invariant across model generations or architectures** — i.e., that there is some fixed absolute-token threshold that applies model-to-model. The evidence points the opposite way: Chroma, RULER, and NoLiMa all show substantial model-to-model variation in *where* degradation begins and how steep it is, even among models with similar claimed windows.

## Sources investigated

### 1. Liu, Lin, Hewitt, Paranjape, Bevilacqua, Petroni, Liang — "Lost in the Middle: How Language Models Use Long Contexts"

- **Citation:** Nelson F. Liu, Kevin Lin, John Hewitt, Ashwin Paranjape, Michele Bevilacqua, Fabio Petroni, Percy Liang. *Transactions of the Association for Computational Linguistics (TACL)*, 2024. Originally posted to arXiv 2307.03172, July 6, 2023. https://arxiv.org/abs/2307.03172 ; ACL Anthology version: https://aclanthology.org/2024.tacl-1.9/ ; code/data: https://github.com/nelson-liu/lost-in-the-middle
- **What it actually demonstrates:** Two tasks — multi-document QA and key-value retrieval — where the researchers hold the *number of input documents* (1, 10, 20, 30 — not absolute token count as the manipulated variable) roughly fixed per condition and vary the *position* of the relevant document/pair within that fixed-size context (tested positions such as 0, 4, 9, 14, 19 within a 20-document set). Verbatim finding: "performance is often highest when relevant information occurs at the beginning or end of the input context, and significantly degrades when models must access relevant information in the middle of long contexts, even for explicitly long-context models."
- **Verdict:** Adjacent to the absolute-vs-percentage claim, not direct evidence for it. This paper's manipulated variable is *position within* a context of a given size, not the *size* of the context itself relative to a model's max window. It is frequently over-cited in practitioner discourse as general evidence that "longer context = worse performance"; that is not what it tested. Relevance to claim (a) (synthetic retrieval degradation): direct and central — this is the origin of the positional U-curve finding. Relevance to claim (b) (agentic/coding quality): none — no coding or multi-turn agentic task is tested.
- **Caveats:** Document-count-based length manipulation, not token-based; models tested are 2023-era (pre-dating most 128K+/1M-token frontier models); single-turn retrieval/QA tasks only.

### 2. Hsieh, Sun, Kriman, Acharya, Rekesh, Jia, Zhang, Ginsburg (NVIDIA) — "RULER: What's the Real Context Size of Your Long-Context Language Models?"

- **Citation:** Cheng-Ping Hsieh, Simeng Sun, Samuel Kriman, Shantanu Acharya, Dima Rekesh, Fei Jia, Yang Zhang, Boris Ginsburg. arXiv:2404.06654, April 2024 (NVIDIA). https://arxiv.org/abs/2404.06654 ; code: https://github.com/NVIDIA/RULER
- **What it actually demonstrates:** A synthetic benchmark extending NIAH with multi-needle variants, multi-hop tracing, and aggregation tasks, evaluated on 17 long-context LLMs across 13 tasks. Critically, RULER evaluates every model at the *same set of absolute lengths* — "4k, 8k, 16k, 32k, 64k, 128k" — regardless of each model's claimed maximum window, then defines each model's "effective context length" as the longest length at which it still beats a Llama2-7B (4K-context) baseline. Verbatim: "while these models all claim effective context of 32K tokens or greater, only half of them can maintain satisfactory performance at the length of 32K," and a model trained specifically for a 1M-token window ("LWM") "performs worse than Llama2-7B even at 4K."
- **Verdict:** **Partially supports** the absolute-vs-percentage claim — this is the closest thing found in this search to a genuine cross-model, same-absolute-length comparison across models with different claimed maximum windows, and its direction is consistent with "bigger window ≠ bigger high-quality zone." It is not a clean ablation of the absolute-vs-percentage question, since RULER's stated research question is "claimed vs. effective context length," not "does degradation track absolute tokens or window fraction." Relevance to (a): direct and central. Relevance to (b): none — synthetic retrieval/aggregation tasks only, no code or agentic evaluation.
- **Caveats:** 2024-era models (pre-dates several current frontier releases); synthetic tasks (retrieval, tracing, aggregation, not real-world document understanding); "effective context length" metric depends on an arbitrary baseline-model choice (Llama2-7B) as the bar.

### 3. Bai, Tu, Zhang, Peng, Wang, Lv, Cao, Xu, Hou, Dong, Tang, Li — "LongBench v2: Towards Deeper Understanding and Reasoning on Realistic Long-context Multitasks"

- **Citation:** Yushi Bai, Shangqing Tu, Jiajie Zhang, Hao Peng, Xiaozhi Wang, Xin Lv, Shulin Cao, Jiazheng Xu, Lei Hou, Yuxiao Dong, Jie Tang, Juanzi Li. arXiv:2412.15204, December 2024. https://arxiv.org/abs/2412.15204 ; code/data: https://github.com/THUDM/LongBench
- **What it actually demonstrates:** 503 multiple-choice questions with contexts from 8K to 2M words across six realistic task categories (single/multi-doc QA, long in-context learning, long-dialogue understanding, code-repository understanding, long structured-data understanding), collected from ~100 domain experts. Human baseline under a 15-minute time limit: 53.7% accuracy. Best model answering directly: 50.1%; a model using extended reasoning (o1-preview): 57.7%. The dataset schema labels each example's length as "short," "medium," or "long," implying a length-bucketed breakdown exists in the benchmark's released data/leaderboard, but the fetched paper text and repository README did not surface a specific length-bucketed accuracy table in the portions retrieved.
- **Verdict:** Adjacent — it is a realistic, human-benchmarked long-context evaluation, and one of its six task categories ("code repository understanding") is the closest primary source found to a large-context, real-world code comprehension task, but it does not report — or at least this search could not confirm it reports — degradation curves as an explicit function of absolute length across models with different max windows. Relevance to (a): moderate, via its length-tagged QA/reasoning tasks. Relevance to (b): weak-to-moderate — "code repository understanding" is present but is a comprehension/QA task, not agentic multi-turn editing.
- **Caveats:** Multiple-choice format (susceptible to guessing/elimination strategies); could not directly confirm quantitative length-bucketed results from the fetched text; this document does not independently verify a length-bucket table beyond noting the schema supports one.

### 4. Chroma — "Context Rot: How Increasing Input Tokens Impacts LLM Performance"

- **Citation:** Kelly Hong, Anton Troynikov, Jeff Huber. Chroma technical report, July 2025. https://research.trychroma.com/context-rot (redirects to https://www.trychroma.com/research/context-rot) ; code: https://github.com/chroma-core/context-rot
- **What it actually demonstrates:** 18 models (Claude Opus 4/Sonnet 4/3.7/3.5/Haiku 3.5; OpenAI o3/GPT-4.1 family/GPT-4o/GPT-4 Turbo/GPT-3.5 Turbo; Gemini 2.5 Pro/Flash, 2.0 Flash; Qwen3 235B/32B/8B) tested across several task families: NIAH variants manipulating needle-question semantic similarity, distractor count, needle-haystack similarity, and haystack structure (logical order vs. shuffled); a "LongMemEval" conversational-QA task comparing ~113K-token full prompts against ~300-token focused versions; and a "repeated words" task at word counts from 25 up to 10,000. Verbatim finding: "as context length increases, performance consistently degrades across all models" on the repeated-words task, and "even a single distractor reduces performance relative to the baseline." A notable, counterintuitive finding: "models perform worse when the haystack preserves a logical flow of ideas" — shuffling sentences *improved* performance, evidence that some degradation is driven by increased plausible-but-wrong content, not length alone. The report's own limitations discussion flags: "a common limitation … is the tendency to conflate input length with task difficulty," and it does not report a systematic percentage-of-window-normalized comparison across models — it evaluates each model largely against absolute token positions and lengths, with some window normalization only where needed (e.g., "for Qwen models, we apply the YaRN method to extend from 32,768 to 131,072 tokens").
- **Verdict:** Partially supports the general degradation claim; **adjacent, not direct evidence**, on the specific absolute-vs-percentage question — the report does not systematically compare degradation curves normalized by each model's own maximum window against degradation curves plotted by absolute position across models. This is explicitly a practitioner/industry technical report, not peer-reviewed; Anthropic's own documentation cites it by name as the origin of the "context rot" framing it uses. Relevance to (a): direct and central, and the broadest single study in terms of model count and task variety found in this search. Relevance to (b): none — no code-generation or agentic task is included.
- **Caveats:** Not peer-reviewed (industry technical report); the authors' own stated limitation about conflating length with difficulty; task selection emphasizes synthetic/near-synthetic retrieval and repetition tasks, not real-world document or code understanding; LLM-judge scoring introduces its own noise (report uses "an aligned GPT-4.1 judge").

### 5. Modarressi, Deilamsalehy, Dernoncourt, Bui, Rossi, Yoon, Schütze (Adobe Research) — "NoLiMa: Long-Context Evaluation Beyond Literal Matching"

- **Citation:** Ali Modarressi, Hanieh Deilamsalehy, Franck Dernoncourt, Trung Bui, Ryan A. Rossi, Seunghyun Yoon, Hinrich Schütze. *ICML 2025* (accepted); arXiv:2502.05167, submitted February 7, 2025. https://arxiv.org/abs/2502.05167 ; code: https://github.com/adobe-research/NoLiMa
- **What it actually demonstrates:** Extends NIAH by minimizing lexical overlap between the "needle" and the question, forcing models to rely on latent/semantic association rather than literal string matching, on 13 LLMs claiming ≥128K-token support. Verbatim: "while they perform well in short contexts (<1K), performance degrades significantly as context length increases. At 32K, for instance, 11 models drop below 50% of their strong short-length baselines." GPT-4o drops from 99.3% (short context) to 69.7% (32K). The authors attribute the decline to the attention mechanism finding literal-match-free retrieval harder as context grows, not to window-fraction effects per se.
- **Verdict:** Supports the general absolute-length degradation claim (a); silent on absolute-vs-percentage, since all 13 models share a roughly comparable ≥128K claimed window and the study does not stratify by window size. Relevance to (b): none — synthetic retrieval only, no code/agentic tasks.
- **Caveats:** Synthetic needle-set construction; single-needle retrieval-style task; peer-reviewed (ICML 2025) which strengthens its trust level relative to non-reviewed technical reports.

### 6. Du, Tian, Ronanki, Rongali, Bodapati, Galstyan, Wells, Schwartz, Huerta, Peng — "Context Length Alone Hurts LLM Performance Despite Perfect Retrieval"

- **Citation:** Yufeng Du, Minyang Tian, Srikanth Ronanki, Subendhu Rongali, Sravan Bodapati, Aram Galstyan, Azton Wells, Roy Schwartz, Eliu A Huerta, Hao Peng. *Findings of EMNLP 2025*; arXiv:2510.05381, submitted October 6, 2025. https://arxiv.org/abs/2510.05381
- **What it actually demonstrates:** Across 5 open- and closed-source LLMs on math, question-answering, *and coding* tasks, the authors show performance degrades 13.9–85% as absolute input length increases *even when retrieval is verified perfect* — including a condition where all irrelevant tokens are masked so the model can only attend to the relevant tokens, and a condition where relevant evidence is placed immediately before the question. Verbatim: "the sheer length of the input alone can hurt LLM performance, independent of retrieval quality and without any distraction." All tested lengths remained "well within the models' claimed lengths" (i.e., this is degradation with no window-boundary or overflow effect involved). They also propose a mitigation (having the model recite retrieved evidence first), which improved GPT-4o's RULER score by up to 4 points.
- **Verdict:** **Supports** the core premise that absolute length itself — not merely retrieval difficulty — degrades performance, and is one of only two peer-reviewed sources found here (with NoLiMa) with this level of experimental control isolating length from retrieval/distraction confounds. It does **not** address the absolute-vs-percentage-of-window question — models are compared against their own baselines at varying absolute lengths, not against each other at matched percentage-fill or matched absolute-length-with-different-max-windows. Relevance to (a): direct and central. Relevance to (b): **the strongest evidence found in this entire search for claim (b)** — coding tasks are explicitly included in the 5-model, 3-task-family evaluation — though this is still single-shot code-reasoning-style evaluation with an automatic checker, not multi-turn agentic tool use or iterative code editing.
- **Caveats:** 5 models only; "coding tasks" here are not defined as multi-file/multi-turn agentic coding — the paper does not describe agent-loop or tool-use settings; peer-reviewed (EMNLP 2025 Findings), a meaningfully stronger trust signal than the non-reviewed sources on this list.

### 7. Pan, Williams — "Context Is Not Comprehension"

- **Citation:** Alex Pan, Mary-Anne Williams. arXiv:2506.04907, submitted June 5, 2025. https://arxiv.org/abs/2506.04907
- **What it actually demonstrates:** Introduces "Verbose ListOps" (VLO), embedding deterministic nested arithmetic (MAX/MIN/SUM operations) inside narrative text so that a model must track intermediate values through "narrative anchors" rather than explicit numerals. Evaluated on 10 models spanning claimed context windows from 128K to 1M tokens, on ~10,000-token narratives. Verbatim: "models which solve raw ListOps with ≈100% accuracy collapse on VLO after only 10k tokens" — e.g., Gemini 2.5 Pro goes from 100% (bare ListOps) to 55.3% (VLO); DeepSeek V3 from 93.7% to 25.1%. Authors' conclusion: "parameter scale or context window size alone cannot bridge this weakness."
- **Verdict:** Adjacent — the models compared do span different claimed max windows (128K–1M), and larger claimed windows visibly do not prevent large drops at a fixed, comparatively short (10K-token) absolute length, which is directionally consistent with "bigger window ≠ bigger high-quality zone." But the paper's manipulated variable is reasoning-step density/narrative complexity, not a controlled absolute-length-vs-window-size design, so this is suggestive rather than a direct test. Relevance to (a): moderate — this is a reasoning-over-context task, adjacent to pure retrieval. Relevance to (b): none — no coding tasks.
- **Caveats:** Not (as far as could be confirmed) published in a peer-reviewed venue at the time of this search; small, novel benchmark (VLO) without independent replication found; only one fixed length condition (~10K tokens) was described in the fetched text, limiting any length-curve analysis.

### 8. Wang, Min, Zou — "Intelligence Degradation in Long-Context LLMs: Critical Threshold Determination via Natural Length Distribution Analysis"

- **Citation:** Weiwei Wang, Jiyong Min, Weijie Zou. arXiv:2601.15300, submitted January 7, 2026. https://arxiv.org/abs/2601.15300
- **What it actually demonstrates:** Defines "intelligence degradation" as a >30% task-performance drop and, using a dataset of 1,000 samples spanning 5–95% of a single model's (Qwen2.5-7B) maximum context length, identifies a "critical threshold" at 40–50% of maximum context length, where F1 drops from 0.55–0.56 to 0.3 (a 45.5% relative degradation).
- **Verdict:** This is the one source found in this search that explicitly frames its result in *percentage-of-window* terms rather than absolute tokens — but it tests **only one model** (Qwen2.5-7B) and does not compare against models with different maximum windows, so it cannot itself adjudicate whether the 40–50%-of-window threshold would recur at a different absolute token count on a model with a different max window (the central open question). It should be read as weak, single-model evidence *for the percentage-of-window framing*, which is the opposite direction from RULER's implication — a genuine tension in the literature that this search did not find resolved anywhere. Relevance to (a): direct. Relevance to (b): none.
- **Caveats:** Very recent (January 2026), three-author preprint with no evidence of independent replication or peer review found; single 7B-parameter model; results may not generalize to frontier-scale models or to models with substantially different maximum windows (e.g., 1M-token models).

### 9. Laban, Fabbri, Xiong, Wu (Salesforce Research) — "Summary of a Haystack: A Challenge to Long-Context LLMs and RAG Systems"

- **Citation:** Philippe Laban, Alexander R. Fabbri, Caiming Xiong, Chien-Sheng Wu. arXiv:2407.01370, July 1, 2024. https://arxiv.org/abs/2407.01370
- **What it actually demonstrates:** A methodological critique-and-replacement for NIAH: the authors argue "Needle-in-a-Haystack lacks complexity" because it reduces to simple lexical retrieval, and propose "SummHay" — a task requiring summarization of repeated insights across many documents with precise source citation, scored on Coverage and Citation. Across 10 LLMs and 50 corresponding RAG systems, "even systems provided with an Oracle signal of document relevance lag our estimate of human performance (56%) by 10+ points," and "without a retriever, long-context LLMs like GPT-4o and Claude 3 Opus score below 20% on SummHay."
- **Verdict:** This is not itself a length-vs-window study; it is included because it is a peer-reviewed-adjacent, well-cited primary source directly critiquing NIAH's evidentiary limits, which the research brief explicitly asked to include. It supports the broader point that synthetic single-needle retrieval accuracy overstates real long-context capability, and underscores why NIAH-style results (bucket 1, above) should not be over-read as evidence about complex task quality. Relevance to (a): supports the critique of NIAH-style methodology broadly. Relevance to (b): none — summarization/citation task, not coding.
- **Caveats:** 2024-era models; summarization-and-citation task, not a length-degradation study per se — cited here for its methodological critique, not as length-curve evidence.

### 10. Greg Kamradt — "Needle In A Haystack" (original methodology)

- **Citation:** Greg Kamradt, original NIAH test/visualization, first publicly documented around November 8, 2023 (X/Twitter thread and associated code, e.g. https://x.com/GregKamradt/status/1729573848893579488; widely re-implemented, e.g. https://github.com/Arize-ai/LLMTest_NeedleInAHaystack2).
- **What it actually demonstrates:** The original test design — an out-of-place sentence ("The best thing to do in San Francisco is eat a sandwich and sit in Dolores Park on a sunny day") inserted at varying depths (0–100%) within Paul Graham essay excerpts of varying lengths (1K tokens up to each model's context limit), visualized as a depth-vs-length heatmap.
- **Verdict:** Treated here strictly as **the definition of a benchmark format**, not as evidence for the degradation claim. It is not peer-reviewed, not a formal paper, and is a practitioner artifact (a demo/visualization shared on social media and in a blog-style writeup) — exactly the kind of source this research explicitly excludes as evidence, included only because later academic and industry work (RULER, NoLiMa, Chroma) explicitly builds on and critiques its methodology.
- **Caveats:** No statistical rigor, no peer review, single-needle/single-model-family demo; depth is reported as a percentage of a given context length, but that context length was itself capped at each tested model's maximum window in the original demo, so even here percentage-within-length and absolute-length were confounded together, not separated.

### 11. Anthropic — "Effective context engineering for AI agents"

- **Citation:** Anthropic Engineering blog, published September 29, 2025 (alongside the Claude Sonnet 4.5 release). https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
- **What it actually demonstrates:** Anthropic's own framing of context engineering as "the set of strategies for curating and maintaining the optimal set of tokens … during LLM inference." It argues that context is "a critical but finite resource" and that the practical question is "what configuration of context is most likely to generate our model's desired behavior" — advocating for the smallest set of high-signal tokens, curated examples, and careful tool/history management, rather than maximizing how much can be stuffed into the window.
- **Verdict:** Adjacent/supporting for the general degradation claim (Anthropic's own operating assumption, stated as an engineering premise, not as an experimentally reported result with numbers). It does not state or provide evidence for the absolute-vs-percentage framing specifically, nor does it cite a study that isolates that variable. It is Anthropic's own vendor guidance, and should be read as such — a design philosophy grounded in their internal experience building Claude Code and other agents, not a controlled study.
- **Caveats:** No primary experimental data presented in the post itself; it is prescriptive/practitioner guidance from the model vendor, not an evaluation report.

### 12. Anthropic — Claude Code documentation and session-management guidance

- **Citation:** Claude Code docs, "Explore the context window," https://code.claude.com/docs/en/context-window (accessed 2026-09-03); Claude blog, "Using Claude Code: session management and 1M context," https://claude.com/blog/using-claude-code-session-management-and-1m-context (accessed 2026-09-03).
- **What it actually demonstrates:** These are product/mechanics documentation, not research. The session-management post states explicitly and by name: "context rot is the observation that model performance degrades as context grows because attention gets spread across more tokens, and older, irrelevant content starts to distract from the current task" — with the citation given as Chroma's Context Rot report (source 4, above). It further explains the mechanism as a transformer-architecture consequence ("LLMs are based on the transformer architecture, which enables every token to attend to every other token across the entire context. This results in n² pairwise relationships for n tokens"), and characterizes the result as "a performance gradient rather than a hard cliff: models remain highly capable at longer contexts but may show reduced precision for information retrieval and long-range reasoning compared to their performance on shorter contexts." Neither document gives a specific absolute-token or percentage-of-window numeric threshold for when compaction becomes necessary; guidance is qualitative ("run it when context starts affecting performance or before a long new task"). The context-window mechanics page documents Claude Code's default 200,000-token window and optional 1M-token variant (`[1m]`), and the compaction system (`/compact`, `/clear`, `/autocompact <token count>`), but again without a stated absolute-vs-percentage rule for degradation onset.
- **Verdict:** Well-established as Anthropic's own stated operating assumption and as the primary-source origin (via citation) of the "context rot" term as Anthropic uses it — but Anthropic is here explicitly citing Chroma's non-peer-reviewed report as its evidentiary basis, not independent Anthropic research. Anthropic's docs do not make or support the absolute-vs-percentage claim specifically; if anything, "gradient, not a cliff" is compatible with either framing, and Anthropic does not adjudicate between them.
- **Caveats:** Product documentation, not a research artifact; evidentiary claims trace back to Chroma's report rather than to independent Anthropic measurement disclosed publicly; no numeric thresholds given.

### 13. Anthropic — "Introducing Claude Sonnet 4.5" (1M-context benchmark caveat)

- **Citation:** Anthropic News, "Introducing Claude Sonnet 4.5," September 29, 2025. https://www.anthropic.com/news/claude-sonnet-4-5
- **What it actually demonstrates:** In its SWE-bench Verified reporting, Anthropic states: "a 1M context configuration achieves 78.2%, but we report the 200K result as our primary score as the 1M configuration was implicated in our recent inference issues" (200K configuration: 77.2%; a high-compute variant: 82.0%). This is a real-world, vendor-disclosed instance of an agentic coding benchmark score being *reported separately* for a 200K vs. 1M context configuration of the same model.
- **Verdict:** Weak, indirect, and confounded evidence — the stated reason for the score gap being flagged is an "inference issue" (an infrastructure/reliability caveat), not a stated claim about degradation-by-design at longer context. It should not be read as evidence that the 1M configuration is inherently lower-quality at matched task difficulty; Anthropic's own framing attributes the discrepancy to an operational issue, not to a context-length-driven capability gap. Included here for completeness and because it is one of the only places a frontier lab publishes same-model, same-benchmark scores at two different context-window configurations side by side.
- **Caveats:** Explicitly confounded by a disclosed "inference issue"; a single data point on a single benchmark (SWE-bench Verified) with no other length-stratified detail provided; does not isolate context length as the causal variable.

## Where popular framing outruns the evidence

- **"Lost in the Middle proves that longer context = worse output."** The paper is frequently invoked this way in practitioner discourse, but it tested *position within a fixed-size context*, not degradation as a function of increasing size. It says nothing directly about whether a 30-document context is worse than a 10-document context in aggregate — its finding is about *where* in the context the answer sits, holding size within each condition constant.
- **"Needle-in-a-haystack results show models handle long context well/poorly."** NIAH-style green heatmaps are widely cited as evidence of strong long-context capability, and NIAH failures are cited as evidence of weak capability — but multiple primary sources here (RULER, NoLiMa, Summary of a Haystack) explicitly argue vanilla NIAH is too easy (exploitable via literal lexical matching) to license either conclusion about real task quality. "Nearly perfect NIAH, large RULER degradation" is RULER's own headline contrast.
- **"Context rot is a peer-reviewed finding."** It is not, in the strict sense. The term and its most-cited empirical backing trace to a single non-peer-reviewed industry technical report (Chroma, July 2025), which Anthropic's own documentation cites by name as the source. That report is methodologically serious (18 models, released code, multiple task families) but has not been through academic peer review, and its authors explicitly flag the length/difficulty confound as an open limitation in their own report.
- **"A 1M-token window has the same quality profile as a 200K window, just extended."** No primary source directly measures this. The closest data point (Claude Sonnet 4.5's 200K-vs-1M SWE-bench scores) is explicitly confounded by a disclosed infrastructure issue rather than isolating context-length effects, and RULER's cross-model evidence (a different generation of models entirely) only shows that claimed window size is a poor predictor of effective performance in general — it does not measure the *same* model at two window configurations in a clean, unconfounded way.
- **"Degradation kicks in at X% of the window" or "degradation kicks in at X tokens," stated as a general rule.** Only one source found here (Wang, Min & Zou, a small, very recent, non-peer-reviewed single-model preprint) states a percentage-based threshold, and it tested exactly one 7B model. No source states or supports a general absolute-token rule that would apply across model families. Anyone asserting a specific number for either version of this rule, across models, is going beyond what the public primary-source literature currently supports.
- **"Coding-agent quality specifically degrades with context length" — treated as if it were as well-established as the retrieval-benchmark findings.** It is not. Only one peer-reviewed source in this search (Du et al., EMNLP 2025 Findings) includes coding tasks at all, and even there the coding evaluation is single-shot and checker-graded, not a multi-turn agentic session with tool use and iterative editing. Claims about agentic coding session quality specifically are, at most, a plausible extrapolation from the retrieval-benchmark literature plus vendor guidance (Anthropic's context-engineering blog) — not a directly measured, publicly documented finding. This gap should be stated plainly rather than papered over with retrieval-benchmark citations, which measure a different phenomenon.
