# Eval health audit — 2026-06-09

Audited at harness commit `ddd4008` against `evals/AUDIT.md`.
Baselines referenced: `tier1_2026-06-05.json`, `tier2_2026-06-06.json`.
Grader selftest: `uv run evals/grader_selftest.py --judge` → PASSED
(23 code fixtures + 3 judge known-negatives, judge cost ~$0.10).

## (a) Findings that can make numbers misleading

1. **Tier-1 is fully saturated.** All 12 quality cells (tests_pass,
   acceptance_checks across tasks 01–06) sit at **1.00 ±0.00** in the pinned
   baseline. The tier can no longer discriminate between variants on quality;
   any tier-1 A/B difference now lives entirely in cost/latency/diff-size, and
   small "quality regressions" there are more likely grader or environment
   noise than capability. This matches the earlier memory-A/B verdict.
   *Suggestion:* treat tier-1 as a regression smoke gate only; add a hard-mode
   tier (multi-file features, underspecified bug reports, refactor-under-test
   constraints) before drawing any more quality conclusions from tier-1.
   The pending template-slimming A/B should be judged primarily on tier-2.

2. **Judge diff truncation is close to real diff sizes.** MAX_DIFF_CHARS is
   24,000; tier-2 baseline diff_size means run 146–490 lines (≈6–20K chars),
   so task 09 (489.67 ±88.12 lines) already grazes the cap on bigger trials.
   Once a diff exceeds the cap, `implementation_fidelity` is judged on a
   silently clipped prefix — missing pieces in the tail are invisible to the
   judge, which biases fidelity *upward* exactly on the largest changes.
   *Suggestion:* raise the cap for backend tasks or truncate head+tail with an
   explicit `[N lines omitted]` marker so the judge knows it saw a partial
   diff; log a flag in the result when truncation fired.
   **Fixed 2026-06-09:** `_truncate_head_tail()` keeps head and tail with an
   explicit omission marker; `result.json` now carries
   `judge_inputs_truncated` so over-cap trials are visible. Selftest covers
   the helper (tail survival is a known-bad fixture).

   **Addendum 2026-06-10:** hard-mode tasks 10–13 were built and validated
   (vague-symptom planted bug, cross-module feature, restraint task, and a
   real no-greppable-keyword ORM count-inflation bug with an unprompted
   class-audit sweep). Result: 7/7 perfect quality trials across BOTH an
   opus-default arm and a sonnet-low arm. The SDLC harness's own
   plan→build→test-with-retries loop absorbs this entire difficulty class —
   quality cells on realistic single-task backend work do not discriminate
   between reasonable arms. The arms DO separate cleanly on cost
   (~$1.5–2.2 vs ~$0.9–1.3) and wall time (13–16 vs 5–13 min). Conclusion:
   treat quality cells as a regression gate; run A/Bs on the cost/latency/
   retries/diff-size axes the suite already measures; if quality
   discrimination is ever needed, it requires count-based graders (e.g.
   sweep-completeness ratios over many instances) or harness-handicap arms
   (no test retries), not harder one-shot tasks.

## (b) Findings that add noise or limit generality

3. **`tests_pass` exit-code fallback can mint a silent 1.0.** When the test
   command emits no parseable summary, the grader falls back to the exit code
   (graders.py:199–201). A misconfigured `test_command` that succeeds while
   running zero tests would score 1.0 with nothing verified ("no answer"
   conflated with "pass"). The selftest pins the current behavior; the planted
   risk is task-authoring, not code. *Suggestion:* return a `no_summary`
   sentinel instead of 1.0 when returncode==0 and no summary parsed, and let
   compare.py render it like "-".
   **Fixed 2026-06-09:** exit 0 with no parseable summary now returns
   `"no_summary"` (excluded from aggregation like `"-"`); selftest pins it
   as a known-bad fixture. Dirty exit without a summary remains 0.0.

4. **Baseline snapshots don't record provenance.** Snapshot JSON carries
   variant/created/tasks but not the harness git SHA, grader version, or judge
   prompt version. A future grader tweak silently breaks comparability with
   pinned baselines. *Suggestion:* add `harness_commit` (and `judge_model`) to
   the snapshot dict in compare.py `--snapshot`.
   **Fixed 2026-06-09:** `build_snapshot()` records `harness_commit` and
   `judge_model`; old snapshots still load (keys are optional on read).

5. **Judge caveats (accepted, documented):** single combined call scores both
   dimensions (atomic separate calls preferred when they start to disagree);
   judge is same model family as SUT (self-preference — read scores as
   relative between arms, not absolute); judge determinism unmeasured (re-run
   2–3× before letting a judge score decide anything on its own). Known
   negatives now verified by the selftest.

6. **One-directional task set.** All 9 tasks reward making changes; nothing
   checks restraint (a task where the right answer touches one file and the
   failure mode is collateral edits). diff_size partially proxies this but is
   unscaled. *Suggestion:* one "surgical change, leave X untouched" task with
   an acceptance check asserting the untouched paths are byte-identical.

7. **`wall_minutes` includes rig overhead.** Agent retries, backoff sleeps,
   and the 30s hang-recovery grace all land in the same number as model
   latency. Fine for "what a run costs you", not for model-speed comparisons.

8. **Fixed `/tmp/eval*.json` paths in acceptance checks** (e.g. task 03) are
   safe while trials run sequentially; they collide if trials ever
   parallelize. Cheap future-proofing: derive the path from the task id +
   trial when that day comes.

## What's in good shape (checked, no action)

- **Infra/task separation:** `classify_status()` three-way status, infra never
  scored, runner aborts after 2 consecutive infra errors.
- **State isolation:** fresh copy + git baseline per trial; backend DB
  dropped/recreated and node_modules cloned from the vendored install.
- **Ground truth unreachable:** task YAMLs/acceptance checks stay in the
  harness; `prepare_target()` copies only the target tree.
- **Memory leakage is by design and gated:** seed stores contain task answers
  for the memory A/B; default runs pass `--no-memory`, seeded runs are
  labeled. Reference solutions exist: every task has fully-ok baseline trials
  (single flake: one task-08 trial, acceptance 0.93 ±0.12).
- **Cost hygiene:** SUT cost from API-recorded `total_cost_usd`; judge cost
  separate (now selftest-enforced); judge model fixed across arms.
- **Observability:** per-agent JSONL, final objects, and prompt files
  persisted, including for the judge.
- **Variance:** mean ± stdev across 3 trials in compare.py; eval config is
  the production `travis_sdlc.py` path (divergences: `--skip-document`,
  `--diff-base HEAD`, both deliberate).
